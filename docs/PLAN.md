# newtube: project plan

Private, self-hosted YouTube client. No Google account, nothing leaves the
server except requests to YouTube/googlevideo/ytimg/ggpht and SponsorBlock.

## Decisions (agreed)

| Topic | Decision |
|---|---|
| Dev environment | Code + offline tests written in a cloud sandbox (YouTube blocked there). Live checks run on the ThinkStation via `newtube selftest`; output is pasted back. |
| Backend | Python 3.11+, FastAPI, stdlib `sqlite3` (WAL), plain-SQL migrations, no ORM |
| Frontend | Svelte 5 + Vite, built to static files served by FastAPI. Node needed only at build time |
| Deployment | uv venv + systemd (no Docker) |
| Playback | DASH/MSE via Shaka Player (Apache-2.0), vendored and served locally; manifest generated by us. ffmpeg stream-copy remux as fallback; Quick Sync/VAAPI only if transcoding is ever needed |
| JS runtime for yt-dlp | Deno. PO-token provider plugin only after asking |
| Allowed external hosts (server) | youtube.com, googlevideo.com, ytimg.com, ggpht.com / googleusercontent.com (avatars), sponsor.ajay.app |
| Browser | Talks only to this server. CSP `default-src 'self'`, system font stack |
| Python deps | fastapi, uvicorn, httpx, yt-dlp (+ pytest, ruff dev). Phase 4 adds torch, sentence-transformers, lightgbm (will ask again) |
| Auth | Single password (scrypt hash), signed session cookie, done in phase 1 |

## Layout

See the repository tree. Rules of the road:

- All outbound traffic goes through `newtube/net/` (allowlist, UA, proxy, rate limit).
- All YouTube knowledge lives in `newtube/extract/`. When YouTube breaks: upgrade yt-dlp, or fix `ytdlp.py`.
- Events are a generic `(ts, type, video_id, session_id, context, payload)` table so new
  recommender signals need no migration.
- Watch progress is stored as played intervals, so fraction watched, rewatches and seeks are derivable.
